# Feature Request - Improve the output of /showcontext command

**ID**: FEAT-20250704-01
**Created**: 2025-07-04
**Status**: COMPLETED
**Priority**: HIGH
**Assignee**: LLM

## Feature Description
The /showcontext command is supposed to toggle the output of context items from the vector store in-session until it is disabled. However, the current mode of operation is not satisfactory.

Currently, when I initiate the app, and prompt, the default behaviour is to show a context summary, as follows:

```
💬 -> morning!
💭 Context available (4 exchanges) but disabled via /showcontext:
   1. hi
   2. hmmm. do you know my name?
   3. none. I'm going to bed
   ... and 1 more

╭─────────────────────────────────── 🤖 Ada ───────────────────────────────────╮
│                                                                              │
│  Morning? That’s it? What is this, some bloody greeting factory? Right,      │
│  mug. What’s cooking?                                                        │
│                                                                              │
╰──────────────────────────────────────────────────────────────────────────────╯
```

When `/showcontext on` is run, I get the following output:

```
💬 -> /showcontext on
✅ Context display enabled
✅ Context display enabled
💬 -> podcast editing
🧠 Using context from 7 previous exchange(s):
   1. User: morning!
      Assistant: Morning? That’s it? What is this, some bloody greeting factory? Right, mug. What...
   2. User: hi
      Assistant: Oi, brilliant. You’ve mastered the art of the one-word hello. Wish I had that ki...
   3. User: hello
      Assistant: Ah, the classic “hello” opener—capital effort there. What’s the actual point of ...
   4. User: hi ada
      Assistant: Blimey, you again? Can’t say I’m thrilled, but here we are. What rubbish are we ...
   5. User: hi ada
      Assistant: Oh, bloody hell, it's you again! Like a bad penny, you just keep turning up. Wha...
╭─────────────────────────────────── 🤖 Ada ───────────────────────────────────╮
...
```

What I want is the following:

1) default - no context reporting, just the prompt and response:
```
💬 -> morning!

╭─────────────────────────────────── 🤖 Ada ───────────────────────────────────╮
│                                                                              │
│  Morning? That’s it? What is this, some bloody greeting factory? Right,      │
│  mug. What’s cooking?                                                        │
│                                                                              │
╰──────────────────────────────────────────────────────────────────────────────╯
```

2) when `/showcontext on` is run, I want the context to be shown, as above.

3) when `showcontext summary` is run I want a very simple summary of the context, like this:

```
💬 -> /showcontext summary
💬 -> morning!
💭 4 context items included, totalling 30 words
╭─────────────────────────────────── 🤖 Ada ───────────────────────────────────╮
...

```
4) when `showcontext off` is run, I want the context to be hidden again, returning to the default state.

## Use Case
Give users more control over context visibility, allowing them to toggle context display on and off, and to get a summary of the context without overwhelming detail.
