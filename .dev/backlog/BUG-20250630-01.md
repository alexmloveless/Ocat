# Bug Report: Vector Index Rebuilding Performance Issue

**ID**: BUG-20250630-01
**Created**: 2025-06-30
**Status**: OPEN
**Priority**: HIGH
**Assignee**: LLM

## Problem Description
The `_rebuild_index()` method in vector store is called for every new exchange, rebuilding the entire Annoy index from scratch, causing significant performance degradation as conversation history grows.

## Steps to Reproduce
1. Start a long chat session with Ocat
2. Add multiple exchanges to build conversation history
3. Observe increasing response time as history grows
4. Performance degrades noticeably with each new exchange

## Expected Behavior
Vector index should be updated incrementally when new exchanges are added, maintaining consistent performance regardless of conversation history size.

## Actual Behavior
Application becomes increasingly slower with each new exchange as the entire Annoy index is rebuilt from scratch.

## Environment
- OS: All platforms
- Language/Runtime: Python 3.x
- Dependencies: Annoy, OpenAI API

## Error Output
```
# No error but performance degradation observable
# O(n) operation for each new exchange
```

## Files Likely Involved
- `src/ocat/vector_store.py:175` - `_rebuild_index()` method
- Related vector store operations

## Additional Context
- Critical issue from code quality report
- Affects user experience and application scalability
- Proposed solution: Implement incremental Annoy index updates
- Should consider hybrid approach with periodic full rebuilds
