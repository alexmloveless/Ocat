# Bug Report

**ID**: BUG-20250630-09
**Created**: 2025-06-30
**Status**: OPEN
**Priority**: MEDIUM
**Assignee**: Alex

## Problem Description
Vector store performance degrades significantly when adding multiple exchanges due to full index rebuilding on every addition. Adding 10 exchanges takes over 30 seconds, making the system unusable for real-time conversation storage.

## Steps to Reproduce
1. Run performance test with 10 exchanges:
   ```python
   for i in range(10):
       vector_store.add_exchange(
           user_prompt=f"Test prompt {i}",
           assistant_response=f"Test response {i}",
           thread_id="thread1",
           session_id="session1"
       )
   ```
2. Measure time taken for additions
3. Observe exponentially increasing time per addition

## Expected Behavior
- Adding 10 exchanges should take under 10-15 seconds total
- Performance should scale linearly or better with number of exchanges
- Real-time conversation storage should be responsive

## Actual Behavior
- Adding 10 exchanges takes 30+ seconds (failed test assertion)
- Each addition becomes progressively slower
- Performance is unsuitable for real-time use

## Environment
- OS: MacOS
- Language/Runtime: Python 3.12
- Dependencies: annoy, openai, langchain

## Error Output
```
test_performance_with_many_exchanges FAILED
assert 30.706663846969604 < 30.0
```

## Files Likely Involved
- `src/ocat/vector_store.py` (add_exchange method, _rebuild_index method)

## Additional Context
The issue is caused by the _rebuild_index() method being called on every add_exchange() operation. This rebuilds the entire Annoy index from scratch, including regenerating all embeddings, which is O(n) complexity and involves expensive OpenAI API calls for each embedding. This should be optimized to use incremental updates or batch operations.
