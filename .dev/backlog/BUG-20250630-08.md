# Bug Report

**ID**: BUG-20250630-08
**Created**: 2025-06-30
**Status**: OPEN
**Priority**: HIGH
**Assignee**: Alex

## Problem Description
Vector store similarity search always returns the first exchange regardless of query content. The /vquery command and find_similar_exchanges method consistently return the same exchange (usually the first one added) for all search queries, making the similarity search functionality completely non-functional.

## Steps to Reproduce
1. Add multiple diverse documents to vector store:
   - ocat --add-to-vector-store cats.txt ("cats are fluffy pets")
   - ocat --add-to-vector-store dogs.txt ("dogs are loyal animals") 
   - ocat --add-to-vector-store metallica.txt ("metallica plays heavy metal music")
2. Query for specific content: ocat --query-vector-store "metallica"
3. Query for different content: ocat --query-vector-store "dogs"
4. Query for another topic: ocat --query-vector-store "cats"

## Expected Behavior
- Query "metallica" should return the metallica document
- Query "dogs" should return the dogs document
- Query "cats" should return the cats document
- Each query should return the most semantically similar exchange

## Actual Behavior
All queries return the exact same exchange (the first one added - cats document):
```
Result 1:
Exchange ID: 75e83309-6d81-44ac-bf31-0998681bd4af
User: Document: test_cats.txt
Assistant: cats are fluffy pets
```

## Environment
- OS: MacOS
- Language/Runtime: Python 3.12
- Dependencies: annoy, openai, langchain

## Error Output
```
Debug output shows Annoy index has correct number of items but search always returns [0]:
All similar indices (full ranking): [0]
Annoy index built with 3 items (expected 3)
```

## Files Likely Involved
- `src/ocat/vector_store.py` (find_similar_exchanges method)
- `src/ocat/commands/vector_commands.py` (VectorQueryCommand)

## Additional Context
This is a critical bug that makes the core vector memory functionality unusable. The issue appears to be in the Annoy index search mechanism where get_nns_by_vector consistently returns only index 0, despite the index containing multiple properly stored items with different embeddings.
