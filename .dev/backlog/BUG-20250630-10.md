# Bug Report

**ID**: BUG-20250630-10
**Created**: 2025-06-30
**Status**: OPEN
**Priority**: HIGH
**Assignee**: LLM

## Problem Description
ChromaDB telemetry system is causing errors due to method signature mismatch in the capture() method. This results in failed telemetry events being logged during application startup and collection creation.

## Steps to Reproduce
1. Run `ocat --config local_config/ada_config.yaml`
2. Observe error messages in console output
3. No interaction with model required - errors occur during initialization

## Expected Behavior
Application should start without telemetry errors and ChromaDB should initialize cleanly

## Actual Behavior
Telemetry errors are logged:
- "Failed to send telemetry event ClientStartEvent: capture() takes 1 positional argument but 3 were given"
- "Failed to send telemetry event ClientCreateCollectionEvent: capture() takes 1 positional argument but 3 were given"

## Environment
- OS: MacOS
- Language/Runtime: Python 3 (conda ocat env)
- Dependencies: ChromaDB 0.5.23

## Error Output
```
Failed to send telemetry event ClientStartEvent: capture() takes 1 positional argument but 3 were given
Failed to send telemetry event ClientCreateCollectionEvent: capture() takes 1 positional argument but 3 were given
```

## Files Likely Involved
- `src/ocat/vector_store.py` (ChromaDB Settings configuration)

## Additional Context
ChromaDB version 0.5.23 has a telemetry system that sends events like ClientStartEvent and ClientCreateCollectionEvent. The telemetry can be disabled by setting anonymized_telemetry=False in the ChromaDB Settings configuration. This is a known issue with ChromaDB where there's a method signature mismatch in the telemetry capture() method.
