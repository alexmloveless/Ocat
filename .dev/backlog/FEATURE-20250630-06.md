# Feature Request: /remember command

**ID**: FEATURE-20250630-06
**Created**: 2025-06-31
**Status**: COMPLETED
**Priority**: MEDIUM
**Assignee**: Alex


## Description
A remember command is needed to allow users to store information in the vector store for later retrieval. This will enable the LLM to remember facts, preferences, and other relevant information across sessions.

## Implementation Details

Format: `/remember <type> <text>`

Examples:

```
/remember fact "I have a brother called Bob"
/remember preference "I don't like eating fish much"
/remember crtitcal "If I mention this again, it is very important to me"

```

Types:
fact - General information that may be useful later
preference - User preferences that can help tailor responses
critical - Important information that should be prioritized in responses
nudge - Gentle reminders or suggestions for the user
like - Positive reinforcement for things the user enjoys
dislike - Negative reinforcement for things the user dislikes

When stored the text should be augmented with markup style tags to indicate the type, e.g.:
```
<fact>I have a brother called Bob</fact>
<preference>I don't like eating fish much</preference>
```
These tags will help the LLM understand the context and importance of the information when retrieving it later. 

These should be added to the vector store with appropriate metadata to indicate that they are a "remember" doc and to indicate their type. The LLM should be able to retrieve and utilize this information in future interactions. For the initial iteration these should be retrieved in the same way as any other vector store document, but in the future we may want to implement a more structured retrieval mechanism and possible actions for when they are encountered.

It is also possible in future that these will be queried separately from standard context queries so that they don't impact the results of other queries. For now, they will be treated as part of the standard context.

### Features
- /remember is aliased to /rem and /r
- Add instructions to the base prompt to inform the LLM about the /remember command and how it should handle remembered information explaining each type and its purpose.
- Add a section to the /help command that describes the /remember command and its usage.
- If no recognisable do not add and warn the user
- The text after the type does not need to be enclosed in quotes

## Implementation hints
- Make sure it is easy to extend in the future to allow for more types or different handling of remembered information.
- Remember to update the Project documentation to include the new command and its usage.
