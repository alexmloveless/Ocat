# Feature Request

**ID**: FEAT-20250701-02
**Created**: 2025-07-01
**Status**: OPEN
**Priority**: MEDIUM
**Assignee**: LLM

## Feature Description
Implement sophisticated document chunking for the vector store to replace the current simple truncation approach. Add support for semantic chunking, configurable overlap, and rich metadata for each chunk.

## Use Case
The current vector store uses simple truncation at 1000 characters, which can:
- Cut off important information mid-sentence or mid-concept
- Lose context when documents are longer than the chunk size
- Provide poor retrieval results due to incomplete semantic units
- Make it difficult to work with long documents effectively

Sophisticated chunking will improve:
- RAG quality by preserving semantic coherence
- Document processing for large files
- Context retrieval accuracy
- User experience when working with long documents

- [ ] Add configurable chunk overlap (e.g., 50-200 characters)
- [ ] Support multiple chunking strategies (fixed-size, semantic, hybrid)
- [ ] Add chunk metadata (source document, chunk index, overlap info)
- [ ] Maintain backward compatibility with existing vector store data
- [ ] Add configuration options for chunking strategy and parameters
- [ ] Update `/vadd` and `/attach` commands to use new chunking
- [ ] Add tests for different chunking strategies
- [ ] Update documentation with new chunking options

## Implementation Notes
- Consider using LangChain's text splitters (RecursiveCharacterTextSplitter, SemanticChunker)
- Add chunking strategy enum: TRUNCATE (current), FIXED_SIZE, SEMANTIC, HYBRID
- Store chunk metadata in ChromaDB metadata field
- Add chunk relationship tracking (previous/next chunk references)
- Preserve existing simple truncation as fallback/default for backward compatibility
- Consider token-aware chunking for better LLM context management

## Additional Context
Reference the newly created documentation at `docs/vector_store/chunking.md` which explains the current simple approach.

Example configuration additions needed:
```yaml
embedding:
  chunk_size: 1000
  chunk_strategy: "semantic"  # truncate, fixed_size, semantic, hybrid
  chunk_overlap: 100  # characters of overlap between chunks
  preserve_sentence_boundaries: true
  max_chunk_size: 1500  # hard limit even for semantic chunks
```

Potential chunking strategies:
1. **TRUNCATE** (current): Simple truncation at chunk_size
2. **FIXED_SIZE**: Split at fixed intervals but respect word boundaries
3. **SEMANTIC**: Split at sentence/paragraph boundaries within size limits
4. **HYBRID**: Semantic splitting with fallback to fixed-size if needed
